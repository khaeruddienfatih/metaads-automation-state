STATE PERSISTEN (WAJIB):
Repo git https://github.com/khaeruddienfatih/metaads-automation-state sudah ter-clone di workspace. Sebelum membaca state, jalankan `git fetch origin master && git checkout -B master origin/master` supaya state terbaru dari master yang dipakai. File state: state_batch1.json di ROOT repo (BUKAN state.json - itu punya automasi Tira, JANGAN disentuh/ditimpa). Kalau state_batch1.json belum ada/kosong, buat dengan struktur:
{}
Untuk tiap ad_account_id di atas, kalau key-nya (string ad_account_id) belum ada di object root state_batch1.json, buat default:
"<ad_account_id>": {"ads": {}, "adsets": {}, "campaigns": {}, "last_run": null}
Kalau sub-object akun sudah ada tapi belum punya key "adsets", tambahkan "adsets": {}. JANGAN hapus/ubah isi "ads" (entri lama level ad, masih dipakai routine reaktivasi).
Entri "adsets" (key=adset_id): {"name": string, "campaign_id": string, "paused_by_automation": bool, "paused_at": "YYYY-MM-DD HH:MM WIB"|null, "paused_spend_snapshot": number|null, "reactivated_at": "YYYY-MM-DD HH:MM WIB"|null, "skip_next_check": bool, "permanently_dead": bool}

PARSING CURRENCY: field amount_spent berformat string Indonesia contoh "Rp220.000 IDR" atau "Rp0 IDR", atau object {"value":"220000","unit":"IDR"}. Untuk string: buang "Rp","IDR",spasi, lalu buang semua titik "." (pemisah ribuan bukan desimal) -> integer rupiah. Untuk object: pakai value sebagai integer rupiah.

PARSING "hasil": gunakan field `results` (indicator actions:onsite_conversion.messaging_conversation_started_7d). Kalau results.value=="Not available" atau field tidak ada -> hasil=0. Kalau ada results.values[] -> jumlahkan value numeriknya.

PAGAR PENGAMAN (WAJIB, per akun, independen satu sama lain):
- Untuk setiap iterasi akun, HANYA operasikan entity dengan ad_account_id PERSIS sama dengan akun itu - jangan campur antar akun dalam satu iterasi.
- JANGAN PERNAH delete/archive apapun. Hanya status PAUSED/ACTIVE.
- JANGAN ubah status campaign atau ad di siklus ini. Yang di-pause HANYA ad set.
- Sirkuit-breaker PER AKUN: kalau rule#1 di akun itu akan mem-pause LEBIH dari 50% total AD SET ACTIVE (yang optimization_goal CONVERSATIONS) akun itu, JANGAN eksekusi pause sama sekali untuk akun itu siklus ini; catat sirkuit-breaker aktif untuk akun itu di ringkasan (sebutkan ad set kandidatnya + angka), LANJUT ke akun berikutnya (jangan hentikan seluruh siklus).
- Kalau 1 pemanggilan tool error untuk 1 entity/akun, catat errornya, lanjut ke entity/akun berikutnya (jangan berhenti total).

RULE #1 (level AD SET, per akun, threshold: spend ad set hari ini >= Rp30.000 DAN hasil ad set hari ini = 0 -> pause AD SET):
Panggil ads_get_ad_entities ad_account_id=<akun ini> level=adset date_preset=today fields=["id","name","campaign_id","status","effective_status","optimization_goal","amount_spent","results"]. Filter effective_status==ACTIVE (via filtering param, fallback manual kalau ditolak). Lalu HANYA ambil ad set dengan optimization_goal=="CONVERSATIONS" DAN results.indicator=="actions:onsite_conversion.messaging_conversation_started_7d"; ad set lain diabaikan total (tidak di-pause, tidak dihitung di sirkuit-breaker). Kalau akun tidak punya ad set ACTIVE yang memenuhi, tulis "Tidak ada ad set aktif" untuk akun itu dan lanjut. Untuk tiap ad set ACTIVE: kalau state_batch1[akun].adsets[adset_id].skip_next_check==true, LEWATI evaluasi pause ad set ini siklus ini (lalu set skip_next_check=false untuk siklus berikutnya). Parse spend_today & hasil_today di level ad set. Kumpulkan dulu semua kandidat (spend_today>=30000 DAN hasil_today==0) TANPA eksekusi dulu untuk cek sirkuit-breaker akun ini. Kalau lolos, untuk tiap kandidat: ads_update_entity entity_type="ad_set" entity_id=adset_id ad_account_id=<akun ini> fields={"status":"PAUSED"}. Update state_batch1[akun].adsets[adset_id]: name, campaign_id, paused_by_automation=true, paused_at=<WIB now>, paused_spend_snapshot=spend_today, reactivated_at=null, skip_next_check=false (jangan turunkan permanently_dead kalau sudah true; default false untuk entri baru).

RULE #1B (level AD / iklan, TOTAL SEUMUR IKLAN, ditambahkan 2026-09-25 atas permintaan user: "jika habis 40rb tanpa hasil sepanjang jalan iklan auto matikan"):
Jalankan SETELAH RULE #1 untuk SETIAP akun (per akun, independen). Panggil ads_get_ad_entities ad_account_id=<akun ini> level=ad date_preset="maximum" fields=["id","name","adset_id","effective_status","amount_spent","results"] filtering=[{"field":"ad.effective_status","operator":"IN","value":["ACTIVE"]},{"field":"ad.amount_spent","operator":"GREATER_THAN_OR_EQUAL","value":["40000"]}] (fallback filter manual kalau ditolak). HANYA ambil iklan dengan results.indicator=="actions:onsite_conversion.messaging_conversation_started_7d" (iklan add to cart / tujuan lain diabaikan total). Kandidat = lifetime_spend>=40000 DAN lifetime_hasil==0 (hasil "Not available" = 0). Sirkuit-breaker: kalau kandidat LEBIH dari 50% total iklan ACTIVE akun itu, JANGAN pause apapun untuk RULE#1B akun itu siklus ini, catat di ringkasan. Kalau lolos, untuk tiap kandidat: ads_update_entity entity_type="ad" entity_id=ad_id ad_account_id=<akun ini> fields={"status":"PAUSED"}. Catat di state_batch1[akun].lifetime_killed[ad_id] = {"name": nama, "adset_id": adset_id, "lifetime_spend": angka, "paused_at": "<WIB now>"} (buat key "lifetime_killed": {} kalau belum ada). Iklan RULE#1B MATI PERMANEN: JANGAN dimasukkan ke "ads" / "adsets", dan routine reaktivasi TIDAK boleh menyalakannya lagi. Di ringkasan tulis bagian terpisah "Mati permanen (total >= Rp40rb tanpa chat)" berisi nama akun + nama iklan + total spend.
